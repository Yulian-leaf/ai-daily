## 3. 架构详解（核心）

### 3.1 一句话概括

ai-daily 是一个「定时抓取 → LLM 评分 → LLM 总结 → 渲染静态页」的**AI 资讯日报**。全程只有 SQLite 一个持久层，最终产物是一个单文件 `index.html`，通过 GitHub Actions 每天定时跑、推送到 GitHub Pages。

### 3.2 目录结构

```
├── config/
│   ├── sources.yaml        # 信息源清单（rss/arxiv/github/hackernews 四种 type）
│   └── preferences.yaml    # 关键词、抓取窗口、模型、评分阈值、top_n
├── prompts/
│   ├── score.txt           # 「评分」LLM 的提示词模板
│   └── summarize.txt       # 「总结」LLM 的提示词模板
├── src/
│   ├── main.py             # CLI 入口：fetch / summarize / render 三个子命令
│   ├── config.py           # 读配置 + 校验（Config、Models、load_config）
│   ├── models.py           # 数据模型（Item、Score、Summary、Analysis）
│   ├── dedup.py            # URL 去重
│   ├── storage.py          # SQLite 读写（Storage 类）
│   ├── summarizer.py       # 评分 + 总结的流水线
│   ├── llm.py              # LiteLLM 封装（多 provider 统一入口）
│   ├── prompts.py          # 加载/渲染提示词模板
│   ├── logging_setup.py    # 日志初始化
│   ├── fetchers/           # 抓取器（rss/arxiv/github/hackernews + 注册表）
│   └── notifier/
│       ├── web.py          # 渲染 HTML 站点
│       └── labels.py       # 来源 → 友好名称 + 分类（配色）
├── templates/index.html.j2 # 单文件 HTML 模板（Jinja2）
├── tests/                  # pytest 测试（82 个）
└── .github/workflows/daily.yml  # GitHub Actions 定时任务
```

### 3.3 数据流（三阶段）

```
config/sources.yaml ──┐
config/preferences.yaml┤
                      ▼
        ┌───────────────────────────┐
        │ ① fetch：fetchers 异步抓取   │  rss/arxiv/github/hackernews
        │    → URL 去重 → items 表    │   （按源隔离失败）
        └───────────┬───────────────┘
                    ▼
        ┌───────────────────────────┐
        │ ② summarize：               │
        │   scorer 便宜LLM 给每条打分  │  → save_score
        │   ≥阈值 的 top_n 条         │
        │   summarizer 强LLM 总结     │  → save_summary
        │   结果进 summaries 表       │
        └───────────┬───────────────┘
                    ▼
        ┌───────────────────────────┐
        │ ③ render：Jinja2 渲染       │  → site/index.html
        │   今日新增 + 归档分栏        │  → 标记 surfaced_at
        └───────────────────────────┘
```

### 3.4 数据库（两张表）

**items 表** —— 抓取到的原始条目：

| 列 | 含义 |
| --- | --- |
| `url` (主键) | 条目链接，去重的依据 |
| `title` / `content` | 标题 / 正文（或摘要） |
| `source` | 来源标识，形如 `rss:openai-blog`、`arxiv:arxiv-cs-ai` |
| `published_at` | 原文发布时间 |
| `raw_json` | 抓取时的原始 JSON（备用） |
| `first_seen` | 本项目第一次见到该 URL 的时间 |

**summaries 表** —— 评分 + 总结结果：

| 列 | 含义 |
| --- | --- |
| `url` (主键，外键→items) | 对应条目 |
| `score` | 0-10 分 |
| `tags_json` | 主题标签（如 `["LLM","agent"]`） |
| `scorer_model` / `scorer_cost_usd` | 评分用的模型 / 成本 |
| `innovation` / `approach` / `metrics` / `links` / `why_relevant` | 总结出的 5 个结构化字段 |
| `summarizer_model` / `summarizer_cost_usd` | 总结用的模型 / 成本 |
| `created_at` | 评分时间 |
| `surfaced_at` | **首次"上墙"时间**，区分「今日新增」和「归档」的关键 |

### 3.5 `surfaced_at` 的巧思

`render` 时：
- `surfaced_at IS NULL` 的 → 归入「今日新增」栏；
- 渲染完成后调用 `mark_surfaced()` 把它们的 `surfaced_at` 置为当前时间；
- 于是同一天第二次 render 时，「今日新增」就空了，它们全进了「归档」栏。

这就是为什么首页分「今日新增 / 归档」两栏，且不会重复展示。

### 3.6 每个关键模块 / 函数

- `src/config.py`
  - `Config` / `Models` dataclass：配置的强类型容器。
  - `load_config()`：读两个 YAML、校验 sources 必填 `name`/`type`、解析整数阈值（`_parse_bounded_int` 限制取值范围）。
- `src/models.py`
  - `Item`（原始条目）、`Score`（评分）、`Summary`（总结）、`Analysis`（Item+Score+Summary 的联表视图，供渲染用）。
- `src/llm.py`
  - `complete_json()`：用 LiteLLM 调模型，并把返回解析成 JSON。
  - `check_api_keys()`：根据模型字符串的 provider 前缀反查环境变量（`_PROVIDER_ENV`），缺 key 直接报错。
- `src/summarizer.py`
  - `run_summarize()`：整个 ② 阶段。先取 7 天内未评分的条目，`asyncio.gather` 并发打分；按 `score_threshold` 过滤、按分数倒序取 `top_n`；再并发总结。
  - `_score_one()` / `_summarize_one()`：单条打分 / 单条总结，各自 try/except，失败不中断整体。
- `src/fetchers/__init__.py`
  - `_REGISTRY`：`{"rss": "fetch_rss", "arxiv": "fetch_arxiv", ...}` 的注册表。
  - `fetch_all()` / `_run_one()`：并发跑所有源，**单源失败被吞掉**（打 WARNING 返回空列表）。
- `src/fetchers/arxiv.py`：查 arXiv API（`sortBy=submittedDate` 取最新），带一次重试。
- `src/fetchers/github.py`：查 GitHub 搜索 API（按 topic + stars + pushed 时间过滤）。
- `src/notifier/web.py::render_site()`：读 today + archive，用 Jinja2 渲染，写 `index.html`，然后 `mark_surfaced`。
- `src/notifier/labels.py::label_for()`：把 `rss:openai-blog` 映射成友好名「OpenAI」+ 分类「lab」，前端据此给来源徽章配色。
- `src/main.py::main()`：argparse 分发三个子命令 `fetch` / `summarize` / `render`。

### 3.7 模型与成本

「便宜模型打分 + 强模型总结」是成本控制的核心：评分阶段要跑全量候选（70+ 次），总结阶段只跑 top_n（10 次）。`summarize` 结束会在日志打印分阶段成本（由 LiteLLM 的价格表计算）。
