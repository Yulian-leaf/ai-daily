## 2. 逐个文件详解

### 2.1 `src/models.py` — 新增 `WeeklyReport`

```python
@dataclass
class WeeklyReport:
    period: str = "weekly"                       # weekly / biweekly（3.5 预留）
    week_start: str = ""                         # 覆盖起始日 YYYY-MM-DD
    week_end: str = ""                           # 覆盖结束日 YYYY-MM-DD
    title: str = ""                              # LLM 生成的标题
    overview: str = ""                           # 综述正文
    highlights: list[dict] = field(default_factory=list)  # [{field, title, url, summary}]
    trend: str = ""                              # 跨周趋势洞察
    outlook: str = ""                            # 下周展望
    generated_at: str = ""                       # 生成时间（ISO）
```

所有字段给默认值，保证旧代码、旧测试不破坏。

### 2.2 `src/storage.py` — 新增表与存取方法

**建表**（沿用 items / summaries 的建表 + 迁移套路，加到 `_SCHEMA`）：

```sql
CREATE TABLE IF NOT EXISTS weekly_reports (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  period TEXT NOT NULL DEFAULT 'weekly',
  week_start TEXT NOT NULL,
  week_end TEXT NOT NULL,
  title TEXT NOT NULL DEFAULT '',
  overview TEXT NOT NULL DEFAULT '',
  highlights_json TEXT NOT NULL DEFAULT '[]',
  trend TEXT NOT NULL DEFAULT '',
  outlook TEXT NOT NULL DEFAULT '',
  generated_at TEXT NOT NULL DEFAULT '',
  UNIQUE(period, week_start)
);
```

**幂等约束**：`UNIQUE(period, week_start)` —— 同一周期重复生成，覆盖更新而非新增，天然防止重复周报（呼应日报「每日封顶」的幂等思想）。

**新增方法**：

- `save_weekly_report(report)`：`INSERT ... ON CONFLICT(period, week_start) DO UPDATE`（upsert）。
- `get_weekly_reports(period)`：按 `week_start` 倒序取历史周报。
- `get_latest_weekly(period)`：取最新一期（渲染「本期」用）。
- `get_surfaced_since(cutoff, min_score)`：窗口内已上墙日报条目（JOIN items + summaries，`surfaced_at >= cutoff AND score >= min_score`）。
- `_row_to_weekly_report(row)`：行转对象，`highlights_json` 反序列化回 `list[dict]`。

### 2.3 `prompts/weekly.txt` — 周报提示词

- **人设**：AI for Science（AI4S）资深科研编辑。
- **输入**：本期时间范围 `{range}` + 过去 N 天的日报条目清单（每条含子领域、标题、一句话亮点、原文链接）。
- **输出**：只输出严格 JSON（不要 markdown 代码块、不要前后空话）：

```json
{
  "title": "AI4S 周报 · MM-DD ~ MM-DD",
  "overview": "3-5 句综述，讲清本期 AI4S 主旋律",
  "highlights": [{"field": "protein", "title": "...", "url": "...", "summary": "一句话亮点"}],
  "trend": "跨周趋势 / 变化",
  "outlook": "1-2 句下期展望"
}
```

- **硬性要求**：中文、量化优先、避免「显著提升」等空话；`url` 必须原样照抄输入，禁止编造；`field` 用 8 个标准 key；亮点每领域最多 2 条、全篇最多 12 条；标题时间范围固定使用注入的 `{range}`、不要自己推算。

### 2.4 `src/weekly.py` — 生成逻辑（新增）

```python
_MIN_ITEMS = 3                                 # 窗口内条目不足则跳过
_WINDOW_DAYS = {"weekly": 7, "biweekly": 14}
```

- `_one_line(text, limit=80)`：把每条目的长摘要压成 ≤80 字一句话，降低 prompt 体积。
- `_render_weekly_prompt(items, week_start, week_end)`：把窗口条目拼成清单，并注入 `{range}`（`MM-DD ~ MM-DD`）渲染提示词。
- `_generate_weekly(items, cfg, week_start, week_end)`：调 `complete_json`（`max_tokens=4000`），校验 `title/overview/highlights` 必填，组装 `WeeklyReport`。
- `run_weekly(storage, cfg, period)` 流水线：
  1. 算窗口：`week_start = 今天 - N 天`（weekly 7 天 / biweekly 14 天）；
  2. 取输入：`storage.get_surfaced_since(...)` → 窗口内已上墙日报；
  3. 判空：条目 < 3 条 → 跳过生成（返回 `{"skipped": True}`），不发 LLM 调用；
  4. 生成：`_generate_weekly` 调 LLM 出结构化综述；
  5. 入库：补 `period/week_start/week_end/generated_at` 后 `save_weekly_report`（upsert）。

**关键设计**：周报的输入 = 已上墙日报条目，**不重新抓取、不重新打分/总结**——日报已完成筛选与单条总结，周报只做汇总综述，每次仅 1 次 LLM 调用，成本极低（< ¥0.1/次）。

### 2.5 `src/notifier/web.py` + `src/main.py` — 渲染与入口

**`render_weekly(storage, period, subfields, output_dir)`**：读最新一期 + 历史归档，用 Jinja2 渲染 `weekly.html`，复用 `label_for` 过滤器与 `field_labels` 映射，返回 `{"output": "...", "reports": N}`。

**`run_weekly_cmd(args)`**：与 `run_render_cmd` 同构——加载配置 → 打开 storage → 调 `run_weekly` + `render_weekly` → 关闭。

**argparse**：新增 `weekly` 子命令：

```bash

python -m src.main weekly --period biweekly  # 双周报告（14 天，Phase 3.5）
```

## 4. 备忘

- 周报是「top 中的 top」：输入是已上墙日报，不重新抓取/打分/总结，每次只 1 次 LLM 调用。
- 窗口是**滚动式**（今天 - 7 天），未做「严格对齐周一/周四」的日历计算；如需对齐，后续在 `run_weekly` 加日历计算即可。
- `weekly_reports.period` 字段已预留 `biweekly`，Phase 3.5 直接复用，无需改表。
- 前端筛选（Phase 2 的 chips）是纯客户端行为，与本阶段的周报页面互不影响。
- PowerShell 会把 LiteLLM 写 stderr 的警告误判为 exit 1（假失败），判定成功与否以日志 `weekly done` 与产物文件为准。

## 5. 遇到的问题与解决（踩坑记录）

### 5.1 LLM 输出 JSON 被截断

- **现象**：`python -m src.main weekly` 报 `LLMError: could not parse JSON: Unterminated string starting at line 132 ...`——DeepSeek 生成的 JSON 在 highlights 中途被截断。
- **原因**：初版 `max_tokens=2500` 不够。输入把 50 条日报的完整长摘要都塞进 prompt，输出又要求每领域 1-3 条亮点（最多 24 条），输入 + 输出双向超长，模型写到一半触顶截断。
- **解决**（三管齐下）：
  1. 输入侧 `_one_line()` 把每条目的长摘要压成 ≤80 字一句话，降低输入体积；
  2. 输出侧 `max_tokens` 提到 4000；
  3. 提示词限制亮点数量（每领域最多 2 条、全篇最多 12 条）。

### 5.2 标题日期幻觉

- **现象**：周报标题写成「AI4S 周报 · 09-08 ~ 09-19」，而实际窗口是「09-12 ~ 09-19」。
- **原因**：提示词只给条目清单、没给时间范围，LLM 自己推断日期，推出一个错误区间。
- **解决**：把 `week_start/week_end` 以 `{range}` 注入提示词，并明确要求「标题时间范围固定使用给出的范围、不要自己推算」。修复后标题正确显示 `09-12 ~ 09-19`。

### 5.3 PowerShell 误报 exit 1

- **现象**：`weekly` 命令日志已打印 `weekly done ... output=site\weekly.html`，但 PowerShell 显示 `Command exited with code 1`。
- **原因**：LiteLLM 拉取远程模型价格表超时，把警告写到 **stderr**；PowerShell 把原生命令的 stderr 输出当作 `NativeCommandError`，从而误判退出码为 1。
- **解决**：实际 Python 流程已成功（日志 + 输出文件 + 正常 flush 齐全）。判定标准以**日志与产物**为准，不理会这个假退出码。
