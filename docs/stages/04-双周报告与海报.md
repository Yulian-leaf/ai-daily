## 2. 逐个文件详解

### 2.1 `prompts/biweekly.txt` — 双周版提示词

与 `weekly.txt` 同结构（输出同一个 JSON：title/overview/highlights/trend/outlook），但侧重点不同：

- **窗口**：覆盖最近两周；
- **overview**：4-6 句，讲清两周主旋律并点出「第一周 → 第二周」的明显变化；
- **trend**：做**跨周对比**——哪些子领域热度上升/降温、是否有新方向浮现，尽量量化（如「从 X 条增至 Y 条」）。

## 5. 遇到的问题与解决（踩坑记录）

### 5.1 Jinja2 把 `stats.items` 渲染成 dict 的方法对象

- **现象**：海报统计区第一项「抓取条目」的数字渲染成了 `<built-in method items of dict object at 0x...>`，而「总结 70」「已上墙 70」正常。
- **原因**：`get_stats()` 返回的 dict 有个 key 叫 `items`，与 dict 的内置方法 `.items()` **重名**；Jinja2 解析 `stats.items` 时**属性访问优先于 key 访问**，于是取到了方法对象而不是值。
- **解决**：模板改用下标访问 `stats["items"]`（连同 `stats["summarized"]`、`stats["surfaced"]`、`stats["by_field"]` 一并改成下标，统一风格）。
- **教训**：dict 的 key 若与内置方法同名（`items` / `keys` / `values` / `get` / `update` …），在 Jinja2 里必须用 `dict["key"]` 下标访问，不能用点号。

### 5.2 改模板后旧渲染产物不自动更新

- **现象**：改了 `weekly.html.j2` 加周期互跳后，`site/weekly.html` 仍是旧版，没有「双周报告 →」链接。
- **原因**：`weekly.html` 是静态渲染产物，只有重新运行渲染流程才会更新。
- **解决**：重新调 `render_weekly`（纯渲染，不重新走 LLM 生成）刷新 `weekly.html`，避免重复生成浪费一次 LLM 调用。
