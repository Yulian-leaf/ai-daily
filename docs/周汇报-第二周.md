## 一、本周概览

上一周完成了「日报」主线（抓取 → 打分总结 → 渲染 + 8 子领域筛选）。本周在日报之上叠加了**三层内容能力**，让项目从「工具」走向「内容产品」：

1. **周报（Phase 3）**——每周两次（周一、周四）由大模型汇总近期已上墙的日报条目，自动写出一篇结构化的 AI4S 综述；
2. **双周报告（Phase 3.5）**——每两周生成一份深度分析报告，侧重「跨周趋势对比」；
3. **可分享海报（Phase 3.5）**——把最新一期报告渲染成一张竖版海报图，适合朋友圈 / 群聊传播。

三者的共同点：**全部复用已有数据，零额外抓取、零新依赖、成本可忽略**（周报每次仅 1 次大模型调用，约 0.1 元以内）。

## 二、本周完成的工作

### 1. 周报功能（Phase 3）

- **周报生成**：把「本周（周一到周日，按北京时间）已上墙的日报条目」作为输入，让大模型直接产出结构化综述——标题、一句话金句、综述正文、按 8 子领域分组的亮点、跨周趋势、下周展望；
- **数据模型**：新增一张 `weekly_reports` 表，用「周期类型 + 起始日期」作唯一约束，同周期重复生成自动覆盖、绝不重复（幂等）；
- **防幻觉双保险**：① 亮点里的原文链接必须原样照抄输入、禁止编造；② 标题里的时间范围固定注入、禁止大模型自己推算；
- **前端**：日报页加「周报」入口，周报页含本期综述 + 历史周报归档，两页可互相跳转。

### 2. 双周报告（Phase 3.5）

- 新增双周版提示词，覆盖**两个自然周**，额外要求输出「跨周趋势对比」（哪些子领域热度上升、哪些降温、有哪些新方向浮现）；
- **完全复用周报的数据结构和解析逻辑**，只换了提示词和窗口天数——设计周报时就预留了「周期类型」字段，因此双周报告零返工、零改表。

### 3. 海报设计（Phase 3.5，本周亮点）

- **程序化选取 Top 亮点**：不再是「大模型随便挑」，而是按规则确定性选取——8 个子领域各取分数最高 1 条，再从剩余池里取分数最高 2 条（共 ≤10 条），并按分数从高到低排列；
- **分数可视化**：每条亮点右上角显示评分（保留 1 位小数），内容质量一眼可知；
- **零依赖美化**：渐变头图 + 大模型生成的一句话金句（大字展示）+ 8 子领域 emoji 图标 + 子领域分布横向条形图——全程只用 CSS 和已有的文本能力，**不引入文生图、不增加任何 API 成本**；
- **可分享成品**：定尺寸 HTML → 无头浏览器截图，产出竖版 `poster.png`（1080 宽），适合手机长图分享。

### 4. 工程质量

- 自动化测试从上一周 97 个增加到 **105 个**，全部通过；
- 阶段文档、创新点清单、考核复习提纲三份文档同步更新到最新状态。

## 三、技术亮点详解（本周新增 7 个）

### ⑬ 周报 = 日报的二次汇总（不重复抓取/打分）

- **是什么**：周报的输入是「已经上墙的日报条目」，不重新抓取、不重新打分总结。
- **怎么做的**：按时间窗口查出已上墙的日报，拼成清单喂给大模型，直接产出综述。
- **为什么是亮点**：日报已经完成了筛选和单条总结，周报只做「精选中的精选」汇总，每次仅 1 次大模型调用，成本极低。
- **可追问点**：为什么不重新打分？——日报的评分已是质量信号，重复打分既浪费又可能前后不一致。

### ⑭ 周报表唯一约束 + 幂等写入

- **是什么**：周报用「周期类型 + 起始日期」作唯一键，同周期重复生成覆盖更新。
- **怎么做的**：数据库层加唯一约束，写入用「冲突即覆盖」。
- **为什么是亮点**：与「每日名额封顶」同思路——定时任务重跑多少次都不会产生重复周报。
- **可追问点**：周期类型字段为什么预留？——周报 / 双周报告共用一张表，后续扩展零改表。

### ⑮ 防幻觉双保险（链接照抄 + 日期注入）

- **是什么**：两个大模型常见幻觉点，在提示词层就被堵死。
- **怎么做的**：① 要求原文链接必须原样照抄输入；② 把时间范围注入提示词，要求标题固定用它、不要自己推算。
- **为什么是亮点**：周报是给读者看链接的内容，链接错一个就不可信、日期错一个就误导；这两处都是实测踩坑后的修复。
- **可追问点**：更稳的做法是程序按标题反查链接回填（可选加固），当前靠提示词约束已够用。

### ⑯ 双周报告复用周报链路，只换提示词 + 窗口

- **是什么**：双周报告不新建任何表 / 解析逻辑，只是窗口变成两个自然周 + 换成双周版提示词。
- **怎么做的**：按周期类型自动选提示词、自动定窗口天数；输出 JSON 结构与周报完全一致。
- **为什么是亮点**：设计周报时就预留了扩展点，双周报告只加一个提示词文件，零返工。
- **可追问点**：两者的输出结构一样，区别只在提示词要求「趋势」做跨周对比。

### ⑰ 海报程序化确定性选取（8 领域各 1 + 公共池 2 + 分数展示）

- **是什么**：海报 Top 亮点不靠大模型主观挑，而是程序按规则确定选取。
- **怎么做的**：8 个子领域各取分数最高 1 条，再从剩余公共池取分数最高 2 条，按分数降序，右上角显示分数。
- **为什么是亮点**：① 8 领域全覆盖，海报有「全景感」；② 分数可视化，质量一目了然；③ 确定性——每次跑结果一致、可复现。
- **可追问点**：为什么不是纯 top-10 分数？——纯分数会让热门领域霸屏、冷门领域缺席；「每领域 1 条 + 2 补充」是覆盖与质量的折中。

### ⑱ 海报零依赖美化（渐变 + 金句 + emoji + 条形图）

- **是什么**：不引任何文生图 / 图标库，纯 CSS + 大模型文本能力让海报「好看」。
- **怎么做的**：① 渐变头图（CSS 渐变）；② 一句话金句（大模型输出、大字展示）；③ 8 子领域 emoji 图标（代码内置映射）；④ 子领域分布横向条形图（CSS 宽度按最大值归一化）。
- **为什么是亮点**：只有 DeepSeek（无文生图能力）也能做出有设计感的海报；零新依赖、零额外 API 成本。
- **可追问点**：为什么不用文生图？——文生图的中文 / 数字不可控，而海报恰恰依赖精确标题、数字、链接；且 DeepSeek 无文生图，需另配 key。

### ⑲ 海报即「内容产品」

- **是什么**：把日报 / 周报升级成一张可分享的图片。
- **怎么做的**：渲染定尺寸海报 HTML → 无头浏览器截图产出图片。
- **为什么是亮点**：日报是「工具」，海报是「产品」——一张图讲清一周科研热点，适合社交传播，是项目从「工具」走向「产品」的一步。
- **可追问点**：图片怎么生成？——HTML 定尺寸 + 无头浏览器截图，纯静态零构建。

> **一句话总结**：在日报流水线之上，叠加了「周报 / 双周报告」（输入 = 已上墙日报、每次仅 1 次大模型调用、唯一约束幂等、防幻觉双保险）和「可分享海报」（8 领域各取 1 条 + 公共池补 2 条的程序化选取、分数可视化、零依赖美化），把数据日报升级成了可传播的内容产品。

## 四、本周遇到的问题与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| 周报 JSON 输出被截断 | 输入 50 条 + 输出亮点过多，超出单次输出上限 | 输入摘要压成一句话 + 提高输出上限 + 限制亮点数量（三管齐下） |
| 周报标题日期推算错误 | 提示词没给时间范围，大模型自己猜 | 把时间范围注入提示词，要求固定使用 |
| 海报统计数字渲染成一串乱码 | 字典键名与大模型对象的内置方法重名 | 改用下标方式取值 |
| 海报亮点只覆盖前 3 个领域 | 选取依赖大模型输出顺序，没有领域均衡保证 | 改成程序化选取（8 领域各 1 + 公共池补 2） |
| 海报在宽屏下靠左 + 页面无海报入口 | 海报容器没居中；各页导航漏了海报链接 | 容器水平居中；三页导航加海报入口 |
| 改模板后页面不更新 | 静态产物只有重新渲染才会变 | 重新渲染（只渲染、不重新生成，省一次大模型调用） |
| 命令报「失败」但实际已成功 | 某依赖库往错误输出流写警告，被终端误判 | 以运行日志和产物文件为准 |
