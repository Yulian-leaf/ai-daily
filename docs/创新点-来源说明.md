# 创新点来源说明：哪些是原项目就有的，哪些是我们加的

> 一句话结论：原项目 ai-daily 本身已经做对了「骨架」（两阶段流水线、纯静态、去重、失败隔离），
> 我们在骨架上做了 3 处「升级」，又针对 AI4S 场景「原创」了 5 个新能力。

图例：
- 🟢 **原项目就有的** —— 直接继承，没改（或只换了模型/内容）
- 🟡 **在原项目基础上改的** —— 骨架是原项目的，语义/细节我们动了
- 🔴 **我们原创的** —— 原项目完全没有，本次新增

## 二、🟢 原项目就有的（4 个，直接继承）

### ① 两阶段「粗筛打分 + 限量精读」
原项目 ai-daily 一开始就是「便宜模型给全部候选打分 → 贵模型只对 Top N 写摘要」。
我们**只是把模型从 Claude 换成 DeepSeek**（因为便宜、国内可直连），架构完全没动。

### ⑤ 纯静态、无服务器架构
原项目本来就是「单文件 HTML + 浏览器本地收藏 + 内联脚本」，零后端。
我们只是换了页面内容和样式（AI4S 主题、子领域筛选），架构没动。

### ⑥ URL 主键去重 + 幂等写入
原项目就用「链接」当数据库主键：重复抓取自动忽略、重复打分自动覆盖。
我们没动这块。

### ⑦ 细粒度失败隔离
原项目就有「单个信息源挂了不影响其它源」「单条内容失败计数后继续」。
我们没动这块。

## 三、🟡 在原项目基础上改的（3 个，升级）

### ② `surfaced_at` 字段分今日/归档
- **原项目有**：`surfaced_at` 这个「首次上墙时间」字段，用来分今日/归档。
- **但原项目的判定是**：「只要上墙过就进归档」（`surfaced_at` 为空 = 今日）。结果：**同一天跑第二次，今日栏就空了**，演示/调试很不直观。
- **我们改**：改成「按日期零点判定」——今天零点之后上墙算今日，跨天自动掉进归档。好处：同一天重复跑不丢今日内容。

### ⑨ 数据库自动迁移
- **原项目有**：自动检测缺列并补列的迁移机制，但**只迁移了 `surfaced_at` 这一列**。
- **我们加**：沿用了这套机制，又新增了 `field`（子领域）、`summarized_at`（总结时间）两列的迁移。

### ⑩ 可观测性 + 成本打点
- **原项目有**：结构化日志 + 成本统计（通过 LiteLLM 计费）。
- **我们加**：新增了 `backlog`（补总结数）、`purged`（清理数）两个指标，用来验证「补总结」修复是否真的生效。

## 四、🔴 我们原创的（5 个，本次核心贡献）

### ③ 遗留候选补总结 + 陈旧清理
原项目有个 bug：**打了分、够相关、但当天名额被挤掉的内容，永远上不了墙**。
我们加了「补总结池」+「清理超 7 天陈旧记录」，修掉了这个缺陷。

### ④ 8 大子领域分类 + 前端筛选
原项目只有「主题标签」（LLM、agent 这种宽泛标签），**没有子领域**。
我们加了 8 个 AI4S 子领域（打分时归类）+ 前端筛选条。

### ⑧ arXiv 主动限速防 429
原项目只对 arXiv 有一次重试，**没有限速**。
我们加了请求间隔，从源头降低被学术库限流封 IP 的概率。

### ⑪ 单日摘要配额封顶
原项目**没有「每天最多总结几条」的概念**，一天跑两次会导致今日内容翻倍。
我们加了每日封顶：每天最多总结 N 条，重复运行只补剩余名额。

### ⑫ 北京时间 + 首次生成时间固化
原项目页面显示 **UTC 时间**、每次生成都**重新计算时间**。
我们改成北京时间（UTC+8）+ 固定为「第一次生成」的时间。

## 五、答辩话术（可直接背）

> 「我们**保留并吃透了上游 4 个核心架构**（两阶段流水线、纯静态前端、URL 去重幂等、失败隔离），
> 在其上做了 **3 处语义升级**（按自然日归档、字段自动迁移、成本审计补指标），
> 并针对 AI4S 场景**原创了 5 个新能力**（8 子领域分类筛选、补总结清理、接口限速、每日配额封顶、北京时间渲染）。」

## 六、最容易答混的两个点（重点记）

1. **② surfaced_at**：很多人会误以为「分今日/归档」是我们原创的。其实**字段是原项目的**，我们只是把判定从「上墙过就归档」改成「按日期零点」，别把功劳全揽也别全推。
2. **⑨ 迁移 / ⑩ 成本**：这两个**机制原项目就有**，我们只是「多迁移了两列」「多加了两个指标」。说「我们原创」会被懂行的追问穿帮，说「在原有机制上扩展」才准确。
