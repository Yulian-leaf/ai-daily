## 一、项目简介

**背景**：AI for Science（AI4S）是「AI 驱动科学研究」的前沿方向，论文、模型、数据集每天大量涌现。本项目把上游开源项目 ai-daily（AI/Agent 资讯聚合）改造成**面向 AI4S 的科研资讯推送站**——每天自动抓取、筛选、总结、渲染，产出零后端的静态日报。

**核心流水线（每天自动跑一遍）**：

1. **抓取** —— 从 arXiv 学术论文、GitHub 开源项目、各大实验室博客、Nature/Science 等期刊、Hacker News 社区等 16 个信息源自动抓取最新内容，去重后存入本地数据库；
2. **筛选 + 总结** —— 用大模型分两步：先给所有候选**打分**（相关性 0-10 分 + 主题标签 + 子领域归类），再只对**得分最高、最相关的一小批**写结构化中文摘要；
3. **渲染发布** —— 渲染成一个网页文件（今日新增 + 按日期归档 + 按子领域筛选 + 收藏），可直接托管到 GitHub Pages。

**技术栈**：Python + 本地数据库（SQLite）+ 大模型接口（DeepSeek）+ 网页模板渲染。

**工程定位**：fork 自托管、零后端、零运维、成本可控（实测每天约 0.3 元人民币）。

### 3. 数据层设计

- 用**一个「首次上墙时间」字段**自动区分「今日新增」和「归档」：今天上墙的算今日，跨天自动掉进归档，不需要额外的表和标记；
- 用**「总结完成时间」**实现「每日最多总结 N 条」的额度封顶，同一天反复运行也不会重复超量；
- **数据库自动升级机制**：代码升级加新字段时，老数据自动补字段、不丢数据、不用删库重建。

### 4. 流水线健壮性与成本控制

- **两阶段模型调用**：便宜模型全量打分，贵模型只对得分最高的一小批写摘要，把成本压到最低；
- **补总结 + 陈旧清理**：修复了「打了分、过了阈值、却被每日名额挤掉、永远上不了墙」的漏洞——超 7 天的陈旧评分记录自动清理，遗留候选自动补总结；
- **请求限速**：控制对学术数据库的请求节奏，避免被限流封禁；
- **失败隔离**：单个信息源失败、单条内容失败，都不影响整批任务；
- **全程日志 + 成本统计**：每次运行结束能看清「打了多少分、总结了多少条、清理了多少、花了多少钱」。

## 三、技术亮点详解（共 12 个，供答辩展开）

### ① 两阶段「先打分、后总结」流水线（成本控制核心）

- **是什么**：把「判断相关性」和「写摘要」拆成两步。
- **怎么做的**：先用便宜模型给近 7 天所有候选逐一打分（0-10 分 + 标签 + 子领域），再只用较强模型给得分最高、最相关的一小批写结构化中文摘要。
- **为什么是亮点**：打分要跑上百条、总结只跑十来条，把贵的模型调用压到最小，成本差 5-10 倍，是整个系统能每天低成本自动跑的关键。
- **可追问点**：为什么不全用强模型？——贵且慢；打分只需要「相对排序」，不需要高质量长文本。

### ② 用「首次上墙时间」单字段分「今日 / 归档」

- **是什么**：一个时间戳字段，就能区分「今日新增」和「历史归档」，不用建两张表。
- **怎么做的**：每条内容记录「第一次上墙的时间」；今天零点之后上墙 = 今日，零点之前 = 归档。
- **为什么是亮点**：零额外表结构；同一天重复运行内容仍显示在「今日」，跨天自动掉进「归档」，语义完全由日期比较推导。
- **可追问点**：为什么以「今天零点」为界而不是「上次运行时间」？——按自然日分栏更符合「日报」直觉。

### ③ 补总结 + 陈旧清理（修复设计漏洞）

- **是什么**：修一个真实 bug——「打了分、够相关、却被每日名额挤掉」的内容，永远没机会再上墙。
- **怎么做的**：清理超过 7 天的陈旧评分记录；把「本轮新候选 + 上轮遗留候选」合并成一个池子，按得分从高到低取每日名额，不区分新旧。
- **为什么是亮点**：这是从「数据库里堆了几十条死数据」的真实问题反推出来的修复；所有候选来自同一个数据源、天然去重。
- **可追问点**：为什么是 7 天？——超过 7 天的内容时效性差，不值得再补总结。

### ④ 子领域分类 + 纯前端筛选

- **是什么**：打分时让大模型顺手把内容归入 8 个 AI4S 子领域，前端用筛选条分类浏览。
- **怎么做的**：打分提示词要求返回子领域；对越界的归类做兜底（回退为「未归类」）；网页渲染 8 个子领域筛选条，点击即在本地过滤、不重新请求。
- **为什么是亮点**：筛选零后端开销，纯静态站点也能做「分类浏览」。
- **可追问点（三个踩坑）**：① 切换领域时条数不变——数字原本是生成时写死的，改成浏览器动态统计；② 归档条数不更新——归档区块缺少唯一标识，补上即可；③ 今日和归档数量混在一起——改成跟随当前标签页分开统计。

### ⑤ 纯静态零后端前端

- **是什么**：收藏、筛选、标签页切换全部在浏览器完成，不引入任何服务器。
- **怎么做的**：收藏用浏览器本地存储；切换/筛选用内嵌脚本，零网络请求。
- **为什么是亮点**：任何静态托管（GitHub Pages 等）都能跑，零运维、可 fork 自托管。
- **可追问点**：代价是什么？——收藏只存在本地浏览器，不能跨设备同步；要同步就必须上服务器 + 登录 + 数据库，与「零后端」定位冲突，故主动放弃。

### ⑥ 用「链接」做唯一标识，自动去重、幂等写入

- **是什么**：用链接作为内容的身份证，从存储层保证不重复。
- **怎么做的**：链接做主键；重复抓取自动忽略、重复评分自动覆盖；并保证评分记录一定对应已抓取的内容。
- **为什么是亮点**：链接是内容的天然唯一标识；幂等意味着定时任务每天跑多少次都不会产生脏数据。
- **可追问点**：为什么「抓取」和「评分」的去重策略不同？——抓取要保留第一次抓到的原文，评分要保留最新的结果。

### ⑦ 失败隔离（健壮性）

- **是什么**：局部失败不拖垮全局。
- **怎么做的**：抓取按信息源隔离（某个源挂了不影响其它源）；总结按单条隔离（某条失败计数后继续）。
- **为什么是亮点**：定时任务无人值守，任何一条脏数据、一次网络抖动都不该让整批失败。
- **可追问点**：怎么证明生效？——运行日志里的「失败计数」就是可观测证据。

### ⑧ 请求限速（防学术库限流）

- **是什么**：控制对 arXiv 学术库的请求节奏，避免被限流封 IP。
- **怎么做的**：两次请求之间加上间隔。
- **为什么是亮点**：学术库限流有两种——瞬时限流 + IP 冷却，限速从源头降低触发概率。
- **可追问点**：还遇到 VPN 的 socks4 代理不被程序支持的问题，换成 TUN/TAP 模式解决——说明网络链路上「代理协议」也是要排查的一环。

### ⑨ 数据库自动升级（向前兼容）

- **是什么**：老数据升级不用删库重建。
- **怎么做的**：启动时检测旧数据缺哪些字段，自动补上。
- **为什么是亮点**：数据是每天攒下来的资产，升级代码不丢数据。
- **可追问点**：会重复执行出错吗？——补字段前先判断是否已存在，重复执行不报错。

### ⑩ 全程日志 + 成本打点（可观测性）

- **是什么**：每次运行结束，能一眼看清「发生了什么、花了多少钱」。
- **怎么做的**：每个阶段输出统计（抓了多少、打了多少分、总结了多少、清理了多少），每条总结记录自己的模型成本。
- **为什么是亮点**：大模型应用花钱是隐形成本，打点让「花了多少钱」变成可度量的数字。
- **可追问点**：新增的「补总结数」「清理数」统计，就是为了验证修复方案而加的可观测指标。

### ⑪ 每日名额封顶

- **是什么**：同一天不管运行多少次，当天新写的摘要总数不超过每日名额。
- **怎么做的**：记录每条摘要的「总结完成时间」；每次运行先统计「今天已经总结了多少」，只补足剩余名额。
- **为什么是亮点**：从根上堵住「一天运行两次导致今日内容翻倍」的口子；额度由数据驱动，不靠内存状态或锁。
- **可追问点**：为什么用「写摘要时间」而不是「打分时间」？——因为遗留补总结的内容可能很久前就打分了，用打分时间会漏计。

### ⑫ 北京时间显示 + 首次生成时间固化

- **是什么**：页面时间按北京时间显示，且固定为「第一次生成」的时间。
- **怎么做的**：固定 UTC+8 时区（中国无夏令时）；第一次生成时记下时间戳，之后复用不覆盖。
- **为什么是亮点**：国内用户看 UTC 要心算 +8；「生成于」的语义从「最近一次」纠正为「首次」，更符合日报直觉。
- **可追问点**：为什么把首次时间记在生成产物目录而不是数据库？——生成产物本身已被版本管理忽略，标记随产物走、零迁移；代价是删除产物目录会重置首次时间。

> **一句话总结**：一个零后端的 AI4S 日报流水线——便宜模型全量打分 → 强模型只总结每日名额内的高分内容 → 用「首次上墙时间」分今日/归档 → 子领域纯前端筛选 → 北京时间渲染 + 首次生成时间固化 → 链接去重 + 失败隔离 + 数据库自动升级 + 限速 + 成本打点；并用「补总结 + 陈旧清理」修掉了打分未总结条目不上墙的漏洞。

## 四、遇到的问题与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| arXiv 频繁 429（限流） | 高频请求被学术库限流/封 IP | 请求限速 |
| 程序报 socks4 代理错误 | 程序不支持 socks4 代理 | VPN 改用 TUN/TAP 模式 |
| 47 条打过分但从未上墙 | 旧逻辑只挑「未打分」内容，被每日名额挤掉后不再处理 | 补总结机制 + 清理陈旧评分记录 |
| 一天多跑导致「今日新增」翻倍 | 每轮都总结新一批 | 每日名额封顶 |
| 页面时间显示 UTC | 直接用了世界时 | 固定 +8 时区，显示北京时间 |
| 「生成于」显示最近一次 | 每次生成现算时间 | 首次时间固化到标记文件 |
